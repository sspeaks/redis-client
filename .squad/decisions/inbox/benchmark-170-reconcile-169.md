### 2026-09-15: Reconcile benchmark multiplexer stats with admission control
**By:** Benchmark
**What:** Unified `MultiplexerStats` so it now reports both the merged admission-control observability from PR #169 (`muxStatsAdmissionLimit`, `muxStatsWriterBatchLimit`, `muxStatsOutstanding`, `muxStatsPeakOutstanding`) and the benchmark-facing queue/in-flight counters from PR #170 (`statsCurrentQueuedCommands`, `statsQueueHighWater`, `statsCurrentInFlight`, `statsInFlightHighWater`). The reconciled command queue keeps separate queued/active counts and preserves the writer-batch drain/top-up flow introduced on `main`, so benchmark sampling continues to emit the same JSON backpressure shape while reflecting the bounded-admission design.
**Why:** PR #169 and PR #170 changed the same multiplexer internals for different reasons. Keeping only admission totals would lose the benchmark suite's per-queue visibility, while keeping only the old queue counters would drop the new bounded-backpressure diagnostics and batch-limit behavior already merged to `main`. The combined struct preserves both views without changing benchmark artifact shape.
