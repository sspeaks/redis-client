## Codebase Patterns
- `hask-redis-mux/data` was originally a symlink to `../data`. TH `embedFile` paths resolve relative to the CWD at compile time, which cabal sets to the package directory.
- The `cabal.project` has two packages: root `redis-client.cabal` and `hask-redis-mux/` subdir.
- `nix-shell --run "cabal build all"` is the way to build when `cabal` is not on PATH directly.
- `cabal clean` may be needed when changing file layout to clear stale TH caches.
- ripgrep (`rg`) has jemalloc issues on this system; use `grep -rn` instead.
- When moving directories deeper (e.g., `X/` → `Y/X/`), audit all `cd ..` in scripts that previously navigated back to root.
- Cabal supports `../` relative paths in `hs-source-dirs` and `c-sources` in a multi-package project; generates sdist warnings but works.
- `hask-redis-mux/lib` was a symlink (now removed); `../lib/` paths in hask-redis-mux.cabal reference root `lib/` directly.
- `hask-redis-mux/test` was a symlink to `../test` (now removed); hask-redis-mux/test/ is a real directory with unit tests only.
- All three hask-redis-mux subdirs (data, lib, test) originally used symlinks to root; all have been converted to real dirs/paths.
